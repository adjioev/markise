# ADR 0027: Tags

Status: accepted for implementation (issue #246).

## Context

A folder of notes labels them with tags, in two places:

```markdown
---
tags: [project/alpha, idea]
---
Notes for today. #idea #travel/2026
```

The epic for moving a notes folder into Markise (#246) asks for both forms to be indexed per
folder, a tag list in the sidebar, search by tag, and `#tag` drawn as a tag in the rendered view
while the file stays byte for byte as written. Spec 06 §10 describes the syntax; this ADR records
how it is built and where it departs from the spec.

## Decision

**What a tag is.** `#` followed by a tag body (`crates/markise-md/src/tags.rs`):

- the `#` starts the text, or follows white space, `(`, or an emphasis delimiter (`**#tag**`);
  `a#b`, `https://x.com/#frag` and `##x` hold no tag;
- the body is letters, combining marks and digits of any script, `_`, `-`, `/`, other symbols
  (emoji) and the zero-width joiner; it ends at the first other character, so `#tag.` and
  `(#tag)` are `tag`;
- a `/` that ends the body or starts an empty segment is not part of it (`#tag/` is `tag`,
  `#a//b` is `a`); nested tags `a/b/c` count for `a` and `a/b` too;
- a body of digits only is no tag (`#1984`, `#123`); one other character is enough (`#y1984`,
  `#2024/01`);
- never inside code spans or blocks, math, HTML (the tags themselves and the text between an
  inline element's opening and closing tags, `<span> #x </span>`; void elements such as `<br>`,
  comments and self-closing tags enclose nothing), links, autolinks, bare URLs, wikilinks or
  review comments, and never a heading marker (`# Title`).

Tags compare without regard to case; the list shows the first casing in vault-path order.

**Front matter.** The keys `tags` and `tag` (any letter case) with a flow list `[a, b]`, a block
list of `- a` lines, or a scalar split on commas and white space (`a, b c`). A quoted item may
start with `#`. An item that is not a whole tag (`has space`) is ignored. The spec reads only
`tags` (Q-V14); the owner asked for `tag` too, as written by older notes. Other keys, nested
values and JSON front matter are not read for tags.

**Parsing.** `ParseOptions::tags`, default on, setting `markdown.tags`, Preferences → Markdown →
"Tags #tag". Recognition is one pass over the text runs of the parsed inline tree (like bare
URLs): everything that is not text — code, math, HTML, links — has already been taken out, so the
pass cannot disagree with the parser. A tag may span adjacent text nodes (`#snake_case`). Table cells are read one by one
through the same cell reader the editor renders with (`\|` unescaped, inline Markdown never
spanning cells, cells beyond the header's columns left out), so the index lists exactly the tags
the editor draws. The
inline node is `InlineKind::Tag` in `markise-md` and `InlineKind::Tag { name }` in the neutral view,
with one text child that shows the source as written: the tag has no hidden markers, the caret
moves through it like through text, and nothing is ever rewritten.

**Headings.** With tags on, a line that starts with a single `#` directly followed by a tag
(`#idea and more`) is a paragraph with a tag, not a level-1 heading, also in the default
non-strict mode (spec 06 V1.6 b). `# Title`, `##Title` and `#1 Title` stay headings. Spec 01 T2
(`#Title` is an H1 in non-strict mode) holds with tags off. People who write headings without
a space turn tags off.

**Index.** The vault scanner (`markise-engine::vault`) already lists the opened folder in the
background. It now also reads each note once (`vault::tags::read_note_tags`: the same parser,
default options, files over 4 MB skipped, at most 1000 distinct tags per note, deduplicated
through a set so a note with very many tags costs linear time) and keeps the tags per note with the size and
modification time it read. Reading happens on the scanner thread: up to 150 ms inside the batch
that listed the files (a small folder gets one snapshot, with its tags), the rest after the file
list is published, so links resolve while a large folder is still being read; a new command
interrupts the reading, which resumes after it. A folder change re-reads the notes directly in
it whose size or time changed, new notes and nothing else; a rescan compares every note. The
file watcher reports a note written in place (`WatchEvent::NoteChanged`; renames were already
reported), so edits from other programs and saves update the index. The index reflects the
files on disk: unsaved edits are not in it. A snapshot's `TagIndex` lists every tag (parents
before their nested tags) with the notes that have it, in path order, and answers `tag:x`, `#x`
and `x` searches (V12.2: `x` and below, never `y/x`). Hidden folders are never read, as before.

**Rendering.** Layout draws a tag as its text on a rounded pill in the theme's link colour on a
faint tint of it (`Theme::tag_colors`, so every theme has it without a new field). For hit testing
the pill reports the link target `tag:#name` (`markise_layout::TAG_LINK_PREFIX`); the
application turns a Cmd/Ctrl+click on it into the Tags view showing that tag's notes instead of
following a link. Exports write the tag as text; HTML wraps it in `<span class="md-tag">` with a
matching pill style. The source pane colours tags like link text.

**Sidebar.** A Tags activity lists the opened folder's tags as a tree (nested tags indented) with
the number of notes. The Find field filters by part of the name and accepts `tag:x` or `#x`;
Enter shows the notes of the tag it names (or of the first match). A tag shows its notes; a click
opens one. There is no folder-wide text search yet, so `tag:` queries live in this field.

## Consequences

- `#word` at the start of a line no longer becomes a heading while tags are on. This is the one
  change to how existing documents read.
- The scanner reads file contents for the first time. Cost: one parse per note when a folder
  opens and per changed note afterwards, off the UI thread; files over 4 MB are not read.
- Not done (spec 06 P1/P2): tag autocomplete after `#`, sort by count, Cmd+click adding a tag to a
  query, renaming a tag across the folder, invalid front-matter items flagged in the gutter, and
  re-reading the open note's unsaved text.
