# Markise 0.1.0-beta.2

Second public beta of **Markise**, a cross-platform Markdown editor written in Rust. It adds
blocks from a site's block package, Read mode and Practice, sections, callouts, highlights,
image embeds, an image picker, and Linux AppImage and `.deb` packages. Expect rough edges, and
keep backups of important files. User guide:
https://github.com/adjioev/markise/tree/main/docs/user (also on the website).

Everything in [0.1.0-beta.1](https://github.com/adjioev/markise/releases/tag/v0.1.0-beta.1) is still there; this page lists what changed.

## Downloads

| Platform | File | Notes |
|---|---|---|
| macOS 11 or later (Apple Silicon and Intel) | `markise-macos-universal.dmg` | unsigned, see below |
| Windows 10/11 x86_64 | `markise-windows-x86_64.zip` | unsigned, see below |
| Linux x86_64 (glibc 2.35 or later) | `markise-x86_64.AppImage` | **new**: one file for any distribution; needs FUSE (`fuse3`), or start it with `--appimage-extract-and-run` |
| Debian 12, Ubuntu 22.04 and newer, x86_64 | `markise_0.1.0-beta.2_amd64.deb` | **new**: `sudo apt install ./markise_0.1.0-beta.2_amd64.deb` installs `markise` and `markise-cli` with their dependencies, a menu entry, icons and "Open with" for Markdown files |
| Linux x86_64 (glibc 2.35 or later) | `markise-linux-x86_64.tar.gz` | X11 or Wayland |

Verify a download with `SHA256SUMS`: `shasum -a 256 -c SHA256SUMS --ignore-missing`
(macOS) or `sha256sum -c SHA256SUMS --ignore-missing` (Linux).
Each archive also contains `markise-cli` (command line: Markdown round-trip check, HTML
export, block checks), the licences (`LICENSE-MIT`, `LICENSE-APACHE`), `NOTICE` and
`THIRD_PARTY/`. The AppImage also contains the AppImage runtime, whose licences (MIT; libfuse
LGPL-2.1, squashfuse, zstd, zlib, musl) are inside it under
`usr/share/doc/markise/appimage-runtime/`.

## What's new

### Blocks from a site's block package

A document can now use the blocks of a website, described by a **block package** the site owns.
See [Blocks](https://github.com/adjioev/markise/blob/main/docs/user/blocks.md) and [Making block packages](https://github.com/adjioev/markise/blob/main/docs/user/block-packages.md).

- `:::name` containers: parsed as blocks with no fixed list of names, byte-exact in the file, a
  simple card on screen and a labelled frame in exports. Typing `:::name` and Return adds the
  closing line.
- Block packages: `blocks.config.json` binds a folder to a `.tar.gz` by its hash. Nothing is
  written or run before you accept it; the status bar shows the state and offers Stop Using This
  Package.
- The form: every field of a block in a panel beside the document (Edit Block…, ⇧⌘E), including a
  block's argument (`:::name argument`), which is checked with a warning rather than refused.
- Native views (callout, card, choices, media) with typing in place, one undo step per action;
  a package can make them quieter (no tint, no label row, a neutral accent).
- The block library: `/` on an empty line, or Insert Block… (⌥⌘B), inserts what the package
  offers.
- Moving blocks by a handle or with Move Block Up and Down, and Delete Block.
- macOS 14 and later: a block can show as a picture drawn by the site's own code, in a separate
  process with no network and no access to your files. Not interactive. Windows, Linux and older
  macOS show native views or cards for those blocks.
- Switch a block, or all of them, between the native view, the site's picture and the card.
- A `⚠` on a block that does not match what the package expects, with the reasons on hover.
- A package's labels follow the document's `lang`; text from a package is always shown as plain
  data.
- A trailing `{#id}` on a heading (and on a list item inside a block) is hidden in the rendered
  view and left out of exports; the file keeps it.
- `markise-cli blocks check FILE.md` checks a document's blocks against its package, and
  `markise-cli blocks docs` writes a package's blocks and rules as Markdown.
- An example package for a made-up recipe site, in `examples/block-package`
  (`cargo xtask block-package` builds it).

### Read mode and Practice

- **Read** (View → Read Mode, ⇧⌥⌘Y; the status bar switches it too), in any document: nothing can
  be typed, pasted or undone, links open with a plain click, and the file does not change.
  Select, copy and Find still work.
- **Practice**: blocks the package marks as practisable are practised in Read. Answers and
  explanations are hidden; choose answers, Check, Reset, and Show answer for blocks with a
  solution. The status bar keeps a score (`3 of 5`) and Reset All. Nothing is written to disk.
- Hidden content stays hidden: copy, Find, the outline, a table of contents and the Comments
  panel leave it out.
- A block with nothing to reveal is not practised and has no practice controls.
- A package can make its documents open in Read.

### Sections

For a package that declares them, or a document with `authoring: blocks-v3` in its front matter,
a `---` line at the document's level starts a section. See [Sections](https://github.com/adjioev/markise/blob/main/docs/user/blocks.md#sections).

- A quiet numbered divider in the rendered view (or a card per section, if the package asks);
  the first section has no divider and needs none.
- A new section from the block library, with a small form; its `id` is made from the title.
- Move Section Up and Down (⇧⌥⌘↑ / ⇧⌥⌘↓) and Delete Section (⇧⌥⌘⌫) move or remove a section
  as one unit, one undo step each.
- In the outline: sections with their number and the headings under them, a menu per section
  (Move Up, Move Down, Duplicate, Insert After…, Delete) and dragging a section to a new place.
- The status bar names the section at the caret.

### Writing

- **Callouts**: a quote starting with `[!name]` is a coloured block with an icon and a title;
  `-` or `+` after the tag makes it foldable (folding is view state only, the file does not
  change). Callouts nest, sit in lists, and are exported to HTML (a foldable one as
  `<details>`), PDF, PNG and Pandoc formats. See [Callouts](https://github.com/adjioev/markise/blob/main/docs/user/editing.md#callouts).
- **Highlight**: `==text==` is highlighted, in the editor and in exports; Format → Highlight
  (⇧⌘H). On by default, with a setting (Preferences → Markdown) to keep the marks as plain text.
- **Image embeds**: `![[photo.png]]`, `![[photo.png|300]]` and `![[photo.png|300x200]]` show the
  image, found by name in the opened folder as for wikilinks, or next to the note (bmp, gif,
  jpeg, jpg, png and webp). They export as images. An embed of a note (`![[note]]`) shows as a
  link to it.
- **Emoji** that the built-in font lacks are drawn with the system's colour emoji font, in the
  document, the outline, the status bar and the menus.

### Images and diagrams

- A full-window view for images and diagrams: double-click, or the expand button; zoom with the
  wheel, a pinch or `+`/`-`/`0`, drag to pan, Esc to close.
- In the rendered view, images show at most 400 points high, for every document. The file and
  exports do not change.
- **Replace…** and **Edit…** on an image change its path and description from the rendered view.
- An image picker with thumbnails from the document's folder, also for a block's form. A file a
  form takes from outside the folder is now copied in by the attachment rules rather than
  refused.

### Look

- Text on high-density displays is drawn closer to the system's own rendering (no hinting at 1.5
  pixels per point and above).
- Code blocks in the rendered view use a smaller default size (0.82 of the body text); the
  built-in Classic, Modern, Technical and Compact styles keep theirs. An imported theme's
  `.md-fences` font size is now honoured.

### Other changes and fixes

- `markise --version` and `markise-cli --version` print the version.
- Linux desktop entry: categories `Utility;TextEditor;` (was also `Office`, which listed Markise
  twice in some menus); AppStream metadata
  (`share/metainfo/io.github.adjioev.markise.metainfo.xml`) in the tarball and both packages.
- A `<details>` disclosure keeps its `<summary>` title when a block is added or removed
  between the two.
- A folded callout keeps the right extent when an edit ends the quote above it.
- Under the hood: the causes of intermittent test failures were fixed.

## Known limitations

- macOS and Windows builds are not code-signed; macOS builds are not notarized (see below).
- One document per window; no tabs; no search across a folder; links are not updated when a
  file is renamed.
- Paste inserts plain text (no conversion of rich text to Markdown); IME input commits text but
  does not show the composition (preedit) inline.
- Note embeds (`![[note]]`, shown as a link) and block references (`#^id`) are not supported.
- Folding a callout is not saved: it opens as written next time.
- Blocks: site pictures need macOS 14 or later and are not interactive; exports show a block's
  content with its name as a label, not its native view or picture.
- Only flowchart and sequence Mermaid diagrams are drawn; other types show their source.
- Export: no export settings dialog and no saved export profiles; PDF/PNG draw math and
  diagrams as source text; remote and `data:` images are not fetched in PDF/PNG export (a
  placeholder with the alt text is drawn); fonts bundled with an imported CSS theme are not
  used in PDF/PNG export (system fonts are); the Pandoc path cannot be set by hand.
- Shortcuts can be changed only in `settings.json`, and file/view commands cannot be rebound.
- No automatic installation of updates; download new versions from the Releases page.
- Linux: no Flatpak and no apt repository; the AppImage carries no update information.

## Installing

### macOS: opening the unsigned app

The app is ad-hoc signed only (no Apple Developer ID signature, not notarized), so macOS asks
for confirmation on first launch:

1. Open `markise-macos-universal.dmg` and drag **Markise** onto **Applications**.
2. Open Markise from Applications. macOS says it cannot verify the app: click **Done**.
3. Go to **System Settings → Privacy & Security**, scroll to **Security**, click
   **Open Anyway** next to the note about Markise, confirm with your password, then **Open**.
   (macOS 11 and 12: **System Preferences → Security & Privacy → General**.) Apple describes
   this in https://support.apple.com/en-au/102445.

If macOS reports the app as damaged and offers no Open Anyway button, see the troubleshooting
section of the user guide (`docs/user/faq.md`).

Markise registers for `.md` and `.markdown` files: use **Open With → Markise** in Finder, or
make it the default under **Get Info → Open with → Change All…**. The command-line tool
`markise-cli` is in the disk image too; copy it to a folder on your `PATH`.

### Windows

Extract the zip (right-click → **Extract All…**) and run `markise.exe`. If SmartScreen shows
"Windows protected your PC" (the build is unsigned), click **More info → Run anyway**. To open Markdown files with Markise,
right-click a `.md` file → **Open with → Choose another app** → browse to `markise.exe`.

### Linux

Three downloads with the same program; pick one.

**AppImage** (any distribution):

```sh
chmod +x markise-x86_64.AppImage
./markise-x86_64.AppImage FILE.md
# without FUSE: ./markise-x86_64.AppImage --appimage-extract-and-run FILE.md
```

**Debian, Ubuntu and derivatives**, which also installs the libraries Markise needs:

```sh
sudo apt install ./markise_0.1.0-beta.2_amd64.deb
markise FILE.md
# remove: sudo apt remove markise
```

**Archive** (any distribution):

```sh
tar xzf markise-linux-x86_64.tar.gz
cd markise-*-linux-x86_64
./markise FILE.md
# optional: install for the current user (menu entry, icon, "Open with")
mkdir -p ~/.local/bin && cp markise markise-cli ~/.local/bin/
cp -r share ~/.local/
```

Runtime libraries for the AppImage and the archive (normally present on desktop systems):
OpenGL/EGL, libxkbcommon, and Wayland or X11 client libraries; the file dialogs use the XDG
desktop portal.

## System requirements

- macOS 11 Big Sur or later, Apple Silicon or Intel (site pictures of blocks: macOS 14 or
  later).
- Windows 10 or 11, x86_64, OpenGL 3.x-capable graphics driver.
- Linux x86_64 with glibc 2.35 or later (Ubuntu 22.04, Debian 12, Fedora 36 and newer), X11 or
  Wayland, OpenGL 3.x / OpenGL ES 3.0.

## Reporting issues

Please open an issue at https://github.com/adjioev/markise/issues with:
the Markise version (`0.1.0-beta.2`, or `markise --version`), your OS and version, what you did,
what you expected and what happened, and if possible a small Markdown file that shows the
problem. For a problem with blocks, say which block package the document uses.

For crashes, attach the log file `markise.log`. It holds start lines (version, OS), crash
locations with a backtrace and fatal errors — never document contents — and stays under 1 MB
(the previous part is kept as `markise.log.1`):

| OS | Log folder |
|---|---|
| Windows | `%LOCALAPPDATA%\Markise\logs\` |
| macOS | `~/Library/Logs/Markise/` |
| Linux | `$XDG_STATE_HOME/markise/logs/` (usually `~/.local/state/markise/logs/`) |

Starting Markise from a terminal also shows its output there (on Windows too:
`markise.exe FILE.md` from Command Prompt or PowerShell).
