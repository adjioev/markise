# Markise 0.1.0-beta.1

First public beta of **Markise**, a cross-platform Markdown editor written in Rust.
Expect rough edges, and keep backups of important files. User guide:
https://github.com/adjioev/markise/tree/main/docs/user (also on the website).

## Downloads

| Platform | File | Notes |
|---|---|---|
| macOS 11 or later (Apple Silicon and Intel) | `markise-macos-universal.dmg` | unsigned, see below |
| Windows 10/11 x86_64 | `markise-windows-x86_64.zip` | unsigned, see below |
| Linux x86_64 (glibc 2.35 or later) | `markise-linux-x86_64.tar.gz` | X11 or Wayland |

Verify a download with `SHA256SUMS`: `shasum -a 256 -c SHA256SUMS --ignore-missing`
(macOS) or `sha256sum -c SHA256SUMS --ignore-missing` (Linux).
Each archive also contains `markise-cli` (command line: Markdown round-trip check and HTML
export), the licences (`LICENSE-MIT`, `LICENSE-APACHE`), `NOTICE` and `THIRD_PARTY/`.

## What works

- **Editing in three views**: the rendered page (click to place the caret, Markdown markers
  around the caret are revealed), Source Code Mode (⌘/) and Side by Side (⌃⌘/, source next to
  the rendered page, scrolling in step). Undo/redo across views.
- **Formatting**: shortcuts (⌘B, ⌘I, ⌘U, ⌘K, …; Ctrl elsewhere) and the Format and Paragraph
  menus; Markdown typed by hand turns into formatting (`**bold**`, `# ` headings, `- ` lists,
  `> ` quotes); lists with Tab/Shift-Tab, block move up/down; tables with row and column
  commands; task lists; formatting toolbar.
- **Find and replace** in the current document: match case, whole word, regular expressions,
  Replace All as one undo step.
- **Folders and Obsidian vaults**: file tree with new/rename/move to Trash, Quick Open (⌘P),
  `[[wikilinks]]` to notes and headings with ⌘-click, `[[` autocomplete, creating a missing
  note from its link, Back/Forward; `.obsidian/app.json` link and attachment settings are read,
  nothing is written inside `.obsidian/`. Background indexing that follows folder changes.
- **Images**: paste or drop images; they are copied into an `assets` folder next to the note
  (configurable).
- **Comments and suggestions** (CriticMarkup): margin cards or hover bubbles, accept/reject one
  or all, comments panel, Save Copy Without Comments.
- **Large files**: virtualised rendering; files of 4 MiB or more open in two steps (the first
  part is shown while the rest loads — 41–52 ms to the first painted frame for 100 MiB test
  documents in headless measurements, see `docs/adr/0017-progressive-open.md`).
- **Themes and styles**: five styles and colour schemes (Markise, Markise Night, Catppuccin,
  Dracula, Gruvbox, Nord, Rosé Pine, Tokyo Night) chosen separately, bundled community themes
  (Drake, Lapis, Phycat), light/dark following the system, font overrides, zoom, import of CSS
  themes (a supported CSS subset; Theme Report), live reload of edited themes.
- **Code blocks**: syntax highlighting for the common languages (the syntax set of the `bat`
  project; see `NOTICE`).
- **Math**: TeX math, inline and display (KaTeX-compatible layout, bundled KaTeX fonts).
- **Diagrams**: Mermaid flowcharts and sequence diagrams, js-sequence and flowchart.js.
- **Saving and recovery**: safe save (temporary file, then replace), draft backups of unsaved
  changes (on by default) with recovery after a crash, optional autosave (off by default),
  detection of files changed by other programs.
- **Update check**: opt-in automatic checks (asked on first launch) and a manual Check for
  Updates…; a check asks GitHub's API for the releases, so GitHub sees the IP address and the
  app version. No telemetry; updates are never downloaded or installed automatically.
- **Preferences** with search: General, Editor, Markdown, Appearance, Source Mode, Files &
  Images; custom key bindings in `settings.json`.
- **Export** (File → Export, runs in the background with progress and cancel):
  - **HTML** (self-contained, styled with the current theme, math and diagrams as SVG) and
    **HTML without styles**;
  - **PDF**: paginated, selectable text, links, document outline (bookmarks), tagged PDF,
    header/footer template; page size and margins from front matter (default A4);
  - **Image (PNG)**: very tall documents are split into several PNGs;
  - **Pandoc formats** (Word .docx, OpenDocument .odt, RTF, EPUB, LaTeX, MediaWiki,
    reStructuredText, Textile, OPML) — requires [Pandoc](https://pandoc.org) 2.10 or later
    installed separately;
  - "Export with Previous" repeats the last export in the session.
  - From the command line: `markise-cli html FILE.md -o FILE.html`.

## Known limitations

- macOS and Windows builds are not code-signed; macOS builds are not notarized (see below).
- One document per window; no tabs; no search across a folder; links are not updated when a
  file is renamed.
- Paste inserts plain text (no conversion of rich text to Markdown); IME input commits text but
  does not show the composition (preedit) inline.
- Wikilink embeds (`![[…]]`) and block references (`#^id`) are not supported.
- Only flowchart and sequence Mermaid diagrams are drawn; other types show their source.
- Export: no export settings dialog and no saved export profiles; PDF/PNG draw math and
  diagrams as source text; remote and `data:` images are not fetched in PDF/PNG export (a
  placeholder with the alt text is drawn); fonts bundled with an imported CSS theme are not
  used in PDF/PNG export (system fonts are); the Pandoc path cannot be set by hand.
- Shortcuts can be changed only in `settings.json`, and file/view commands cannot be rebound.
- No automatic installation of updates; download new versions from the Releases page.
- Linux: a tarball only (no AppImage, .deb or Flatpak yet).

## Installing

### macOS: opening the unsigned app

The app is ad-hoc signed only (no Apple Developer ID signature, not notarized), so macOS asks
for confirmation on first launch:

1. Open `markise-macos-universal.dmg` and drag **Markise** onto **Applications**.
2. Open Markise from Applications. macOS says it cannot verify the app: click **Done**.
3. Go to **System Settings → Privacy & Security**, scroll to **Security**, click
   **Open Anyway** next to the note about Markise, confirm with your password, then **Open**.
   (macOS 11 and 12: **System Preferences → Security & Privacy → General**.) Apple describes
   this in https://support.apple.com/en-au/102445.

If macOS reports the app as damaged and offers no Open Anyway button, see the troubleshooting
section of the user guide (`docs/user/faq.md`).

Markise registers for `.md` and `.markdown` files: use **Open With → Markise** in Finder, or
make it the default under **Get Info → Open with → Change All…**. The command-line tool
`markise-cli` is in the disk image too; copy it to a folder on your `PATH`.

### Windows

Extract the zip (right-click → **Extract All…**) and run `markise.exe`. If SmartScreen shows
"Windows protected your PC" (the build is unsigned), click **More info → Run anyway**. To open Markdown files with Markise,
right-click a `.md` file → **Open with → Choose another app** → browse to `markise.exe`.

### Linux

```sh
tar xzf markise-linux-x86_64.tar.gz
cd markise-*-linux-x86_64
./markise FILE.md
# optional: install for the current user (menu entry, icon, "Open with")
mkdir -p ~/.local/bin && cp markise markise-cli ~/.local/bin/
cp -r share ~/.local/
```

Runtime libraries (normally present on desktop systems): OpenGL/EGL, libxkbcommon, and
Wayland or X11 client libraries.

## System requirements

- macOS 11 Big Sur or later, Apple Silicon or Intel.
- Windows 10 or 11, x86_64, OpenGL 3.x-capable graphics driver.
- Linux x86_64 with glibc 2.35 or later (Ubuntu 22.04, Debian 12, Fedora 36 and newer), X11 or
  Wayland, OpenGL 3.x / OpenGL ES 3.0.

## Reporting issues

Please open an issue at https://github.com/adjioev/markise/issues with:
the Markise version (`0.1.0-beta.1`), your OS and version, what you did, what you expected and
what happened, and if possible a small Markdown file that shows the problem.

For crashes, attach the log file `markise.log`. It holds start lines (version, OS), crash
locations with a backtrace and fatal errors — never document contents — and stays under 1 MB
(the previous part is kept as `markise.log.1`):

| OS | Log folder |
|---|---|
| Windows | `%LOCALAPPDATA%\Markise\logs\` |
| macOS | `~/Library/Logs/Markise/` |
| Linux | `$XDG_STATE_HOME/markise/logs/` (usually `~/.local/state/markise/logs/`) |

Starting Markise from a terminal also shows its output there (on Windows too:
`markise.exe FILE.md` from Command Prompt or PowerShell).
